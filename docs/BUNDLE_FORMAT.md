# IndexTTS Bundle Format (`.itts`)

## 1. Purpose

`index-tts-bundle` is a portable file format for storing one TTS generation request and its related assets:

- generated audio (single combined output and/or per-segment outputs)
- source prompt text
- speaker reference audio + title
- emotion reference audio + title

The format is designed for long-term compatibility across tools and languages.

## 2. Container

- File extension: `.itts`
- Physical format: ZIP archive
- Required manifest file at archive root: `manifest.json`
- Path separator inside archive: `/` (forward slash)

## 3. Current API behavior mapping

In this repository, current generation flow (`api_server.py` -> `IndexTTS2.infer`) splits text into internal segments, generates per-segment wave chunks in memory, inserts interval silence, then concatenates and saves a single WAV output file.

That means:

- today, writer should use `generated_audio.mode = "combined"` by default
- per-segment files are optional future-compatible data
- per-segment metadata can still be present even if only combined audio is stored

## 4. Archive layout

Example:

```text
example.itts
|- manifest.json
`- audio/
   |- generated/
   |  |- combined.wav
   |  `- segments/
   |     |- 0000.wav
   |     `- 0001.wav
   |- reference/
   |  `- voice_01.wav
   `- emotion/
      `- sample1.wav
```

Only `manifest.json` is mandatory at fixed path. Audio file names are flexible; manifest paths are authoritative.

## 5. Manifest (`manifest.json`)

Manifest must validate against `docs/bundle.schema.json`.
Current recommended manifest target is `version: "1.1.0"`.

### 5.1 Required top-level fields

- `format`: must be `"index-tts-bundle"`
- `version`: manifest version (SemVer), current major is `1`
- `bundle_id`: unique id (UUID/ULID/string)
- `created_at`: RFC 3339 UTC timestamp
- `prompt`
- `playback`
- `generated_audio`
- `reference_audio`
- `emotion_audio`

### 5.2 Prompt

- `prompt.text` (required): original input text
- `prompt.language` (optional): BCP-47 or project-specific language tag
- `prompt.segments` (optional): ordered text segments used/generated by a splitter

`prompt.segments[]` supports:

- `index` (required, zero-based)
- `text` (required)
- `token_count` (optional)
- `start_ms` / `end_ms` (optional alignment hints)

### 5.3 Playback

`playback` is a deterministic playback contract for all clients.

Required fields:

- `default_source`: `combined` or `segments`
- `fallback_order`: ordered array using `combined` and/or `segments`
- `segment_order`: currently must be `index_asc`

Rules:

- If `generated_audio.mode = "combined"`, playback must use combined only.
- If `generated_audio.mode = "segments"`, playback must use segments only.
- If `generated_audio.mode = "both"`, either source can be default, but fallback order must be explicit.

### 5.4 Generated audio

`generated_audio.mode` controls which fields must exist:

- `combined`: requires `generated_audio.combined`
- `segments`: requires `generated_audio.segments`
- `both`: requires both

`generated_audio.combined` and each entry in `generated_audio.segments[]` contain:

- `path` (required, relative ZIP path)
- `mime_type` (required, e.g. `audio/wav`, `audio/ogg`)
- `sha256` (optional but strongly recommended)
- `bytes`, `duration_ms`, `sample_rate_hz`, `channels` (optional metadata)

Each segment also has:

- `index` (required)
- `text` (optional)
- `start_ms` / `end_ms` (optional timeline in combined track)

When segments are present (`mode = segments` or `both`), these fields are required:

- `segment_index_policy`: must be `zero_based_contiguous`
- `segments_count`: total segment count

Segment index contract:

- `index` values must be unique
- minimum index must be `0`
- maximum index must be `segments_count - 1`
- no gaps are allowed (`0..segments_count-1`)

### 5.5 Reference and emotion audio

`reference_audio` and `emotion_audio` require:

- `title` (required, human-readable label)
- `path` (required)
- `mime_type` (required)
- `sha256` (optional but recommended)
- `bytes`, `duration_ms`, `sample_rate_hz`, `channels` (optional)

### 5.6 Generator metadata (optional)

`generator` can include:

- `app` (e.g. `"IndexTTS2 API"`)
- `model` (e.g. `"indextts2"`)
- `settings` (request-time knobs such as `emo_mode`, `temperature`, `top_p`)

## 6. Validation rules

Loader should:

1. Open archive as ZIP.
2. Read and parse `manifest.json` as UTF-8.
3. Validate with `bundle.schema.json`.
4. Ensure each declared `path` exists in ZIP.
5. If `sha256` exists, verify file hash.
6. Reject path traversal (`..`, absolute paths, drive-letter paths).

## 7. Compatibility policy

- Major version change (`1.x` -> `2.x`): breaking manifest changes.
- Minor/patch versions (`1.1`, `1.2`, `1.2.1`): backward-compatible additions.
- Loader profile (recommended runtime): unknown fields should be ignored.
- Schema profile (`bundle.schema.json`): validates core contract and allows unknown extension fields for forward compatibility.
- Strict backend implementations may add extra local checks in addition to schema validation.

## 8. Example manifest (mode=`both`)

```json
{
  "format": "index-tts-bundle",
  "version": "1.1.0",
  "bundle_id": "01JNZFWQ93CZ8D2PS7V7W44ANP",
  "created_at": "2026-02-27T21:30:00Z",
  "prompt": {
    "text": "Hello there. This is a long sentence that may be segmented internally.",
    "language": "en",

      { "index": 0, "text": "Hello there." },

      "path": "audio/generated/combined.wav",

    },

      {
        "index": 0,
```

## 9. Minimal loader algorithm (language-agnostic)

1. Parse `manifest.json`.
2. Validate schema and required runtime checks (segment index contract).
3. Read `prompt.text`.
4. Follow `playback.default_source` and `playback.fallback_order`.
5. If segments are used, play in `segment_order` (currently `index_asc`).
6. Read `reference_audio` and `emotion_audio` by declared paths.
7. Verify hashes when provided (recommended for all assets).
